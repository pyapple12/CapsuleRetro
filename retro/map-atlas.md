## 坐标系与换算

- 单图 16×16 格；数据 (0,0) 在**左下角**，绘制需垂直翻转
- 换算式：`image_px = ( x × S_w, (15 − y) × S_h )`
- S：原生 tile 10×8（图 160×128）；×6 版 tile 60×48（图 960×768，最近邻）
- 指认示例：dark 1 号图（A1 區域）数据格 (0,0) → 原生图像素 (0, 120)
- **世界网格语义**（户外地面/天路）：区域名 `字母数字` = **列字母 A–F（西→东）×
  行数字 1–4（北→南）**，世界 = 6 列 × 4 行；判据 = A1 邻接 N=0/W=0（西北角）、
  A4 S=0（南缘）、F 列全 E=0（东缘），并经官方 in-game world map 参考图比对证实

## 户外渲染规则（游戏 Tab 小地图同款）

每格依次叠画（0 = 跳过）：`surfaceLUT[n0]` → `wallLUT[n1]+16`（n1≠0 且 LUT 值≠0）→
`n2+32`（n2≠0）→ `n3+48`（n3≠0）；帧来自 `OUTDOOR.TIL`（主体 10×8）。

## 户内渲染规则（v16 定案 2026-09-14：ScummVM drawIndoorsMinimap + 官方全城图 1:1 反推）

- 环境集：`wallKind`（偏移 826）→ `[TOWN, CAVE, TOWR, CSTL, DUNG, SCFI]` 对应
  `<名>.TIL`（暗面侧聚类实证：0=五镇、1=下水道矿坑、2=群塔、3=城堡、4=神庙地牢、
  5=逃生艇科幻）；TIL 帧原生 10×8（墙条 14×5 / 5×12 带帧内偏移，非 16×16）
- 地面：**全部格子画 frame 0**（空置格由第 4 遍盖板最终覆盖）
- 地面点缀：CellFlag 低 3 位 surfaceId ≠ 0 **即画** `surfaceLUT[surf]+36` 于
  **(+5,+5)**——ScummVM 权威条件只有 surfaceId 非 0（interface_minimap.cpp:151），
  **LUT[surf]=0 时帧号 = 36 = 水面**（dark124 角落缺水实证，勘误第十四则）
- 墙（帧表，0 = 不画）：西墙 = nibble3 查 A 表、北墙 = nibble0 查 A 表+1（奇数帧，
  东/南墙由邻格的西/北表达）；作用于**原始 nibble**（`mazeLookup` 返回
  `(_data >> shift) & mask`，不经墙 LUT）；空置格（0x8888）跳过墙条
  - A（西）：1→18，2→34，3→22，4→16，5→2，6→30，7→32，8→2，9→20，10→28，11→14，
    12→4（动画栅栏取静帧），13→16，14→24，15→26
  - B（北）：同表 +1（1→19，2→35，…，15→27）
- 空置盖板：**`wallData == 0x8888`（INVALID_CELL，全 nibble=8 实心岩体）最后统一
  整格画 frame 1**——游戏内 INVALID 格恒画 frame 1，官方全城图的"厚墙带"即连续
  f01 砖纹遮罩（v3 的"庭院 n0/n3==8"近似规则作废）
- **画序（v16 四层方程式，用户与官方图 1:1 目测确认）**：地面 → 点缀 → 墙 →
  空置盖板。层级错画即出缺陷：点缀画在墙后会"门贴压墙"、盖板不最后画会
  "地面盖墙"（v4–v15 逐版实证）
- **城镇拼合 = 整城分层**：每层先拼成整城完整画布再逐层叠加（装饰贴片跨分图
  边界的溢出不被裁掉，v4 逐图渲染+不透明贴片架构即因此缺行）；**整组资源上下文
  归锚点**——surfLUT 与 TIL 环境集（wallKind）都取锚点图（ScummVM XeenMap 场景
  资源按 `_mazeData[0]` 加载，scummvm-map.cpp:954；內可玻利斯 35 CAVE + 117
  龍塔第一層 TOWN 官方图实证：塔层成员随锚点渲染，37 组中 14 组为混合环境集）。
  各分图自带 surfLUT 是同组地表类型的错位排列（佛提格市：28=[0,7,9,2]、
  110/111=[0,1,7,9,2]、109=[0,1,7,9]），逐图用自身 LUT 会把室内/草地/道路整体画错
- 单图档案保留自身 LUT 渲染（= 游戏内站在该图时 Tab 小地图的实际观感）

## 勘误与实证记录

1. 单图为 16×16 格（立项备忘初稿误记 22×22）
2. 自渲染地图为游戏数据派生物，版权血统与随包游戏本体一致；相对下载路线的真正
   优势 = 风格可控、不外求
3. ScummVM 自 2.1.0（2019）起官方支持 Xeen（引擎后更名 mm）——勘误 PL008
   "ScummVM 无 xeen 引擎"记录
4. `AAZExxxx.TXT/.HED` = 事件文字/事件头（16 位哈希空间撞车改名产物，OpenXeen 作者
   注佐证），非迷宫几何
5. 迷宫几何不在主 CC：实际存放于 `DARK.CUR / XEEN.CUR`（CUR = current side，非光标）
6. 游戏目录 `XEEN.DAT` = "MZD" 头运行时状态文件，非地图数据
7. **区域名文件两侧各自成套**（PL011.5 live 实证更正，初版"两侧共用表"结论作废）：
   云端 = `XEENxxxx.TXT`（85 个，佛提格市/夜影鎮/靈蛇鎮/矮人礦場/香格里拉/競技場等，
   live 实证 cloud 28 = 佛提格市与游戏内 Tab 显示一致）；暗面 = `DARKxxxx.TXT`；云端
   100+（天路等共用图）无 XEEN 名文件时回落 DARK 名。同号两侧名字不同（如 28 号：
   云端佛提格市 / 暗面水元素平原）
8. 世界网格 = 6 列（字母 A–F，西→东）× 4 行（数字 1–4，北→南）；世界整图初版误作
   4 列 × 6 行转置排布，经用户提供的官方 in-game world map 参考图发现后修正
9. **城镇 = 多图拼合的连续空间**（PL011.6 live 实证；同日经 y.problems#21 修复）：
   佛提格市（cloud 28）邻接 N=110/E=109，城内坐标可超 16（连续坐标系），map 字节
   保持进城锚点号；单图渲染只能画出城市一角——城镇连通分量已拼合渲染
   （37 分量，`city_maps` 段），佛提格市全城布局与粉丝整城图结构吻合
10. **官方全城图渲染模式破解**（y.problems#21，用户提供官方佛提格市实机渲染图
    717×574 像素级反推；图 = 32×32 格 × 原生 10×8 长宽比 × 2.2 等比放大）：
    ①"厚墙带" = `0x8888` 空置格整格画 f01 砖纹遮罩，非墙条帧；②点缀帧带
    （+36）为整格地形画（TOWN.TIL f36–f51 与 OUTDOOR.TIL f00–f15 同艺术：
    38/45/43 = 草地/城内红地/道路）；③城内红地 = f45（红底棕斜杠纹理），草地
    斜杠细节 = 点缀溢出 + 场内 cf00 露底格的自然结果；④**各组共用锚点 LUT**
    （勘误见户内规则 v4）；⑤已知残差：官方图草地内孤立斜杠记号在档案图中
    个别缺失（疑为官方渲染所用存档的探索/物件状态差异），不影响结构
11. TOWN.TIL 与 OUTDOOR.TIL 为同一套瓦片美术的两份排布：OUTDOOR 的 0 帧带
    （f00–f15 地形）== TOWN 的 +36 帧带（f36–f51）；+16 以上为墙条/覆盖层
12. **户内渲染最终方程式 = v16 整城分层**（2026-09-14 定案）：画序四层
    地面 f00 全格 → 点缀 (+5,+5) → 墙条 → 0x8888 盖板 f01 最后；城镇拼合每层先拼
    整城画布再逐层叠。作废记录：v4 的点缀 (+5,+6)（多 1px，用户目测定 +5,+5）、
    "点缀最后画覆盖墙条"（正是"门贴压墙"缺陷来源）、逐图渲染+不透明贴片拼合
    （裁掉跨界溢出导致缺行）。v15 曾出现"分层架构反而更差"的假象，实为收集格子
    时漏做数据行→屏幕行的垂直翻转（数据行 0 在屏幕最南），非架构问题
13. **整城环境集也归锚点**（2026-09-14，用户指出內可玻利斯右半塔层素材与官方不
    符）：ScummVM 场景资源（.til/.gnd/.fwl/surfaceSprites）一律按 `_mazeData[0]`
    （分量第 0 图 = 进城锚点）的 wallKind 加载——37 个拼合分量中 14 个为混合环境
    集（洞穴/塔/下水道锚点 + 相邻 TOWN 塔层成员：cloud025–027、035、038–041、
    050、079–082、dark032），成员一律随锚点 TIL 渲染；单图档案仍保留自身环境集
14. **点缀"LUT=0 跳过"系过拟合，作废**（2026-09-14，用户指出 dark124 每个水域
    角上缺一块水）：ScummVM 点缀条件只有 `surfaceId != 0`，帧号恒为
    `surfaceLUT[surf]+36`——LUT 映 0 时帧号 36 即水面贴图，dark124（SCFI 集，
    锚点 LUT[4]=0）22+3 格中招实证。初版该规则源自佛提格市，但该城非 void 格
    恰好不存在 LUT0 组合，规则从未真正生效也未被子样检验；修正后 dark124-city
    err 60.0→57.1，佛提格/內可玻利斯零回归（86.8 / 93.5）
