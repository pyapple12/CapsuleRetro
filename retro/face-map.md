# XEEN 面容档案（face-map）

> 队伍头像的完整机制与角色对照。配套 `memory_map.json` 的 face1~face6 条目；
> 勘探过程记录见 z.plan.md 附录 PL009。

## 机制

- **face 数组：`0x5A7C:0x0002` 起 6 字节**（按队伍 1–6 号位排列），
  每字节 = 该队员的**名册槽位（0 基）**
- **面容文件号 = 槽位 + 1** → `CHAR{槽位+1:02d}.FAC` → PNG `char{槽位+1:02d}.fac.png`
  （第 N 槽（0 基）用 CHAR(N+1).FAC，与 ScummVM Roster 构造 `char{idx+1}.fac` 一致）
- 创建人物的"选头像"实为**选空槽位**——脸随槽位走，预建与自建角色统一适用
- 验证：五快照（换像前后 ×2、换自建队）+ live REST + 12 角色逐一比对，无一例外

## 资源哈希（ext 提取与命名校验用）

- `资源 id = rot7 累加哈希`：`total = 首字节`，其后每字节 `total = rot7(total) + 字节`
  （16 位循环右移 7 位），**对不含扩展名的 stem 计算**（如 `CHAR01` → `0xd399`）
- 24 对 CHARnn.FAC 名字→资源 id 全吻合；DARK.CC 与 XEEN.CC 的 charNN.fac 内容相同
- 该版 TOC 布局：id u16 + 偏移 3 字节 + 长度 u16（在第 5 字节，非 ScummVM 的第 6 字节）

## 勘误备注（防止重走弯路）

- 队伍记录 `+0xA9` 字节（预建 6/2/8/12/15/7、自建 0）是**预建角色模板号**，
  随角色移动——与面容无关，勿再误认
- 存档名册布局：`DARK01.SAV` 记录区起于 `0xE01`（槽位 0 = 趙金童），步长 354（0x162），
  名字在记录头；`XEEN01.SAV` 同构但基址不同（面容 = 相对槽位 + 3）
- 存档名册中**不存在 face 字段**——脸由槽位推导，"portrait picker"即空槽位选择器
